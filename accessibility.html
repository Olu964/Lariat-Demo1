Accessibility Statement

Lariat is a real-data demo for reviewing Texas legislative records. This statement describes the accessibility support currently implemented, known limitations, and how to report a barrier.

✦ Reviewed September 4, 2026

Our commitment

Lariat aims to support people with different access needs. We use the Web Content Accessibility Guidelines (WCAG) 2.1 Level AA as a development target. This prototype has not been independently audited, formally certified, or evaluated across every browser, screen reader, and assistive technology, so we do not claim full conformance.

Current support

  • Pages use semantic landmarks, headings, lists, native links, native buttons, labeled controls, and native dialog elements where appropriate.
  • Interactive controls have visible :focus-visible styling and can be operated with a keyboard.
  • Bill cards, bill-detail dialogs, subscription forms, live status messages, and note-saving feedback include labels or announcements where implemented. The Pricing page's plan links are intentionally unavailable because the page is covered by the demo overlay.
  • Decorative animation and smooth scrolling are reduced or disabled when the browser requests reduced motion. The bill-feed jump control uses instant scrolling in that mode.
  • Decorative canvas and visual effects are hidden from assistive technology so they do not add unnecessary content to the accessibility tree.
  • The site does not require a mouse or pointer for the available primary navigation, bill filtering, bill details, notes, or subscription controls. The homepage's decorative book interaction is pointer-enhanced only. Pricing plan links are intentionally inert behind the demo overlay.

Known limitations

  • No independent WCAG audit, screen-reader certification, keyboard-only certification, or complete color-contrast review has been completed.
  • The landing page opens a demo notice on the first visit in a browser; it can be closed with its close button, but the interaction and native dialog behavior still need testing across browsers and assistive technologies.
  • Color contrast has not been measured in every light and dark visual state.
  • The subscription flow requires a reachable, correctly configured backend. In local development that is node server/server.js; the public site cannot complete subscriptions unless its API base is configured and the production infrastructure is available.
  • Opening the pages with file:// is unsupported. Use the local backend or another HTTP server.
  • Pricing plan links are unavailable while the demo overlay is active. If that overlay is removed or the interaction is enabled, plan selection is demo-only browser state stored in localStorage; it is not an account, payment control, or server-side authorization feature.
  • Third-party websites and services linked from Lariat are outside Lariat's accessibility and content control.

Feedback and assistance

Report an accessibility barrier to lariatfeed@gmail.com. Include the page address, the task you were trying to complete, the browser or assistive technology involved, and the problem you encountered. We will review reports and work toward an accessible fix.

For privacy requests, please see the Privacy Policy.
